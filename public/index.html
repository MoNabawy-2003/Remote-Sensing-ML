Technical Documentation

Overview

This documentation provides a complete technical reference for the Land Cover Classification workflow. It covers 10-band ENVI feature extraction, transferability across geographic domains, preprocessing safeguards, ground-truth validation, and accuracy reporting.

1. 10-band ENVI Data Extraction

The input pipeline ingests ENVI-compatible Landsat stacks and builds a 10-band feature cube. Seven native Landsat bands are complemented with three spectral indices derived from the stack: NDVI, NDWI, and NDBI. The resulting feature vector preserves both raw reflectance and targeted land-cover signatures (vegetation, water, and built-up).

  • Band stack validation ensures the expected band count before any transformation.
  • NDVI = (NIR - Red) / (NIR + Red) for vegetation response.
  • NDWI = (Green - NIR) / (Green + NIR) for surface water detection.
  • NDBI = (SWIR - NIR) / (SWIR + NIR) for built-up characterization.

2. Model Transferability Strategy

The Random Forest model is trained on Nile Delta scenes and evaluated on Ismailia to verify transferability. This establishes whether learned spectral separability holds across varying regional land-cover distributions and atmospheric conditions.

  • Training datasets are curated from Nile Delta ROIs with balanced class proportions.
  • Testing datasets use Ismailia scenes to stress domain shift and cross-region generalization.
  • Consistent preprocessing ensures the feature pipeline remains invariant between regions.

3. Preprocessing Safeguards

Multiple safeguards prevent runtime failures and improve model stability. Feature-count validation confirms that each pixel contains the full 10-band vector. No-data and NaN masking are applied before scaling, then remaining NaNs are replaced with zeros to avoid scaler crashes.

  • Feature-count validation ensures all required bands and indices are present.
  • NaN/no-data masks remove invalid pixels prior to scaling and prediction.
  • Residual NaNs are replaced with zeros to keep the scaler numerically stable.

4. Ground-truth ROI Validation

Validation uses labeled ROIs aligned with the prediction grid. Ground-truth coordinates are provided in 1-based indexing, then converted to 0-based coordinates to match array indexing in the model pipeline. This alignment ensures that the reference labels and predicted classes map to the same pixels.

  • ROI coordinates are normalized to zero-based indexing before extraction.
  • Pixel-wise labels are collected for evaluation on the predicted raster.
  • Class-level consistency checks validate the ROI mapping against band geometry.

5. Accuracy & Reporting

The evaluation stage extracts Overall Accuracy and a full classification report including precision, recall, and F1-score per class. These metrics are summarized for dashboards and exported for formal reporting.

  • Overall Accuracy computed from correctly classified ROI pixels.
  • Classification report includes per-class precision, recall, and F1-score.
  • Metrics are archived alongside output rasters for audit-ready reporting.
